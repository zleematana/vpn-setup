# vpn-setup

Личный VPN-сервер одной командой: **VLESS + XHTTP + TLS** за nginx.

Снаружи сервер выглядит как обычный сайт с настоящим сертификатом Let's Encrypt:
на любой посторонний запрос открывается страница входа. VPN-трафик идёт обычными
HTTP/2-запросами по секретному пути, который знают только выданные ключи.

## Что нужно

- Сервер на **Ubuntu 24.04** (1 vCPU, 1–2 ГБ памяти хватает), доступ root.
- Домен или поддомен, у которого A-запись смотрит на IP сервера. В Cloudflare —
  режим **DNS only** (серое облако), без прокси.

## Установка

Зайти на сервер по SSH от root и выполнить:

```bash
curl -fsSL https://raw.githubusercontent.com/zleematana/vpn-setup/main/install.sh | bash -s -- vpn.example.com
```

Вместо `vpn.example.com` — свой домен. Через 3–5 минут в терминале будут
ссылки `vless://…` и QR-коды для ключей `phone` и `pc`. Свои имена ключей можно
перечислить после домена:

```bash
curl -fsSL https://raw.githubusercontent.com/zleematana/vpn-setup/main/install.sh | bash -s -- vpn.example.com anna boris laptop
```

Что делает установщик:

- обновляет систему, ставит nginx, certbot, ufw;
- если в `/root/.ssh/authorized_keys` есть ключ — отключает вход по паролю
  (если ключа нет, пароль остаётся, чтобы не потерять доступ);
- открывает только порты 22, 80, 443, включает BBR;
- скачивает последний Xray-core с GitHub и сверяет sha256;
- получает сертификат, продлевает его автоматически;
- делает страницу-заглушку со случайным названием и оформлением, чтобы серверы
  с этим скриптом нельзя было найти по одинаковой странице (свой сайт можно
  положить в `/var/www/files` — он не перезаписывается);
- ставит команду `vpn`, создаёт ключи и проверяет туннель целиком.

Повторный запуск безопасен: ключи и секретный путь сохраняются. Так же
обновляется Xray.

## Управление

На сервере:

```text
vpn list          ключи, кто сейчас онлайн, трафик с запуска xray
vpn add anna      новый ключ: ссылка и QR-код
vpn link anna     снова показать ссылку и QR-код
vpn del anna      отключить ключ
vpn check         проверка: службы, сертификат, настоящий туннель и скорость
vpn restart       перезапустить xray и nginx
```

С компьютера то же самое через SSH: `ssh root@сервер vpn list`.

Ключи добавляются и удаляются без перезапуска: подключённые не отваливаются.
Счётчики трафика обнуляются при перезапуске Xray. Посещённые сайты не
записываются. Торренты и доступ к локальным сетям сервера заблокированы.

## Клиенты

Нужен клиент на **Xray-core**:

| Платформа | Клиент |
|---|---|
| iPhone, iPad | Happ, v2RayTun |
| Android | Happ, v2rayNG |
| Windows, Linux | v2rayN, Happ |

Импорт: скопировать ссылку `vless://…` и в клиенте выбрать «Импорт из буфера»,
или отсканировать QR-код.

**Не работают:** Amnezia VPN (пишет «подключено», но трафик не идёт) и клиенты
на sing-box (Hiddify и подобные) — они не умеют XHTTP.

Если соединение на какой-то сети нестабильно, в настройках ключа поменять
`mode` с `auto` на `packet-up` или `stream-one`.

## Переезд на новый IP с теми же ключами

Ключи привязаны к домену, а не к IP. Если адрес сервера заблокировали:

1. Поднять новый сервер.
2. Скопировать на него со старого `/usr/local/etc/xray/config.json` и
   `/usr/local/etc/xray/client.env` (в тот же каталог).
3. Перевести A-запись домена на новый IP.
4. Запустить установщик с тем же доменом.

У клиентов ничего менять не нужно. Если старый сервер уже недоступен, ключи
придётся выдать заново.

## Где что лежит на сервере

| Что | Где |
|---|---|
| Ключи (конфиг Xray) | `/usr/local/etc/xray/config.json`, прошлая версия — `config.json.bak` |
| Домен и секретный путь | `/usr/local/etc/xray/client.env` |
| Сайт nginx | `/etc/nginx/sites-available/<домен>` |
| Страница-заглушка | `/var/www/files` |
| Сертификат | `/etc/letsencrypt/live/<домен>/` |
| Журнал Xray | `journalctl -u xray` |
