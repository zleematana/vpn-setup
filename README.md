# Свой VPN одной командой

Эта инструкция для тех, кто никогда не настраивал серверы. Ничего программировать
не придётся: нужно будет скопировать одну команду и ответить на три вопроса.

## Что получится в итоге

- Свой VPN-сервер, которым пользуешься только ты и те, кому ты сам дашь доступ.
- **Ключи** — по одному на каждое устройство или человека. Ключ — это длинная
  ссылка `vless://…` и QR-код. Её вставляешь в приложение на телефоне или
  компьютере, нажимаешь «подключить» — и всё.
- Снаружи сервер выглядит как обычный сайт со страницей входа. Проверяющие
  системы видят обычный зашифрованный сайт, а не VPN.
- Потом можно добавлять и отключать ключи, смотреть, кто сейчас подключён и
  сколько скачал, одной короткой командой.

Сколько времени: 15–30 минут, большая часть — ожидание.

## Что понадобится

1. **Сервер (VPS) за границей.** Подойдёт самый дешёвый: 1 процессор, 1–2 ГБ
   памяти, система **Ubuntu 24.04**. После оплаты хостер присылает три вещи:
   **IP-адрес** (вида `123.45.67.89`), **логин** (обычно `root`) и **пароль**.
2. **Домен или поддомен.** Это имя вроде `vpn.example.com`, которое будет вести
   на твой сервер. Без него не получится настоящий сертификат, а без сертификата
   VPN легко отличить от обычного сайта. Если домена нет — самый дешёвый `.ru`
   стоит около 150–300 ₽ в год (reg.ru, nic.ru и другие регистраторы).
3. **Компьютер или телефон**, с которого зайдёшь на сервер. Подойдёт Windows,
   Mac или телефон с приложением Termius.

## Шаг 1. Направь домен на сервер

Нужно создать у домена **A-запись** — она говорит интернету: «это имя живёт вот
по этому IP-адресу». Делается в личном кабинете там, где управляешь доменом
(у регистратора или в Cloudflare), в разделе «DNS» или «Управление зоной».

Добавь запись:

| Поле | Что вписать |
|---|---|
| Тип | `A` |
| Имя (Name, Subdomain) | `home` — получится `home.твойдомен.ru`. Можно любое слово. Или `@`, если VPN будет на самом домене |
| Значение (IPv4, Content) | IP-адрес твоего сервера |
| TTL | по умолчанию или «Auto» |

**Если домен в Cloudflare:** рядом с записью есть облачко. Оно должно быть
**серым** («DNS only»), а не оранжевым. Нажми на него, чтобы переключить.

Запись начинает работать через 5–30 минут (иногда дольше). Проверять самому не
нужно: скрипт на шаге 3 проверит сам и, если надо, подождёт.

## Шаг 2. Зайди на сервер

Заходить будем по **SSH** — это текстовое окно, в котором ты управляешь сервером.

**Windows.** Нажми «Пуск», набери `PowerShell`, открой. Впиши (вместо
`123.45.67.89` — IP твоего сервера) и нажми Enter:

```
ssh root@123.45.67.89
```

**Mac.** Открой программу «Терминал» (через Spotlight: ⌘ + пробел, «Терминал»)
и впиши ту же команду.

**Телефон.** Поставь Termius (App Store или Google Play), нажми «New Host»,
в Address впиши IP, в Username — `root`, в Password — пароль. Подключись.

Что будет дальше:

- При первом входе спросят `Are you sure you want to continue connecting?` —
  напиши `yes` и нажми Enter.
- Спросят `password:` — вставь пароль от хостера и нажми Enter. **Пароль при
  вводе не отображается, даже звёздочками** — это нормально. Вставить в
  PowerShell — правой кнопкой мыши.
- Если всё верно, увидишь строку вроде `root@server:~#`. Ты на сервере.

## Шаг 3. Запусти установку

Скопируй эту команду целиком, вставь в то же окно и нажми Enter:

```bash
curl -fsSL https://raw.githubusercontent.com/zleematana/vpn-setup/main/install.sh | bash
```

Сначала скрипт спросит, **какой это сервер**. Для обычного VPN ответь `1`
(или просто нажми Enter). Вариант `2` — для каскада, о нём в разделе
[«Каскад»](#каскад-российский-вход-перед-заграничным-сервером).

Потом будут три вопроса. Напиши ответ и нажми Enter.

1. **Домен** — впиши имя из шага 1, например `vpn.example.com`
   (без `http://` и без слэшей).
2. **Какие ключи создать** — имена латиницей через пробел, например
   `phone laptop mama`. Если просто нажать Enter, будет два ключа: `phone` и `pc`.
   Добавить ещё можно в любой момент позже.
3. **Выключить вход по паролю?** — **если не уверен, ответь `нет`** (или просто
   нажми Enter). Тогда ты и дальше заходишь на сервер по паролю, как сейчас, а от
   подбора пароля сервер защищён сам. Про вариант «да» — в разделе
   [«Вход по SSH-ключу»](#вход-по-ssh-ключу-по-желанию).

Дальше скрипт всё делает сам, 3–5 минут. Если домен ещё не заработал, он
напишет «Жду, пока запись заработает» и будет ставить точки — просто подожди.

## Шаг 4. Забери ключи

В конце появятся:

- проверка — строчки с ✓, последняя «Всё в порядке»;
- для каждого ключа — **подписка**: ссылка `https://твойдомен/s/…` и под ней
  **QR-код** из квадратиков. Ниже — две запасные ссылки `vless://…` для
  приложений, которые не умеют подписки;
- надпись «Готово. VPN работает».

Подписку можно скопировать (выдели мышью; в PowerShell выделение сразу
копируется) и переслать себе в «Избранное» мессенджера. Если потерял — не
страшно, её всегда можно показать заново: `vpn link phone`.

**Почему подписка, а не ссылка `vless://`.** Ссылка `vless://` — это сами
настройки, записанные в строку: приложение запоминает их один раз. Подписка —
адрес, с которого приложение само забирает настройки и обновляет их. В ней
два пути до сервера (через домен и прямо на IP), и Happ с v2RayTun сами
переключаются на живой, если провайдер испортит один из них. Если сервер
переедет или что-то поменяется в настройках, всё дойдёт само.

**Ключи — как пароли.** Каждый, у кого есть ссылка, может пользоваться твоим
VPN. Отправляй их только тем, кому доверяешь, и лучше личным сообщением.

## Шаг 5. Подключи устройство

Нужно приложение, которое понимает этот тип VPN.

| Устройство | Приложение |
|---|---|
| iPhone, iPad | **Happ** (App Store). Если его нет в твоём регионе — **v2RayTun** |
| Android | **Happ** (Google Play) или **v2rayNG** |
| Windows | **Happ** или **v2rayN** |
| Mac | **Happ** |

**Не подойдут:** Amnezia VPN (напишет «подключено», но интернет работать не
будет), Hiddify и другие приложения на sing-box, Outline, обычные WireGuard и
OpenVPN.

Как добавить ключ (на примере Happ, в других так же):

1. Скопируй подписку `https://…` своего ключа.
2. Открой Happ, нажми **«+»** вверху → **«Вставить из буфера»**.
   Или «+» → **«Сканировать QR»** и наведи камеру на QR-код на экране компьютера.
3. Появится сервер с именем вроде `vpn-phone авто`. Нажми большую кнопку включения.
   В других приложениях могут появиться два сервера, `vpn-phone` и
   `vpn-phone-ip` — выбери любой, а если перестанет работать, переключись на второй.
4. Телефон спросит разрешение на VPN — разреши.

**Проверь, что работает:** открой в браузере сайт `2ip.ru`. Там должен быть
IP-адрес твоего сервера, а не твой домашний.

## Управление: добавить друга, отключить, проверить

Зайди на сервер (как в шаге 2) и вводи команды:

| Команда | Что делает |
|---|---|
| `vpn list` | список ключей, кто сейчас онлайн, сколько скачал |
| `vpn add masha` | создать ключ `masha` — покажет подписку и QR-код |
| `vpn link masha` | снова показать подписку и запасные ссылки ключа |
| `vpn json masha` | тот же конфиг, что в подписке, — чтобы вставить вручную |
| `vpn sub` | пересобрать подписки всех ключей (например, после смены IP) |
| `vpn del masha` | отключить ключ — подписка и ссылки перестанут работать |
| `vpn check` | проверить, что всё работает, и замерить скорость |
| `vpn restart` | перезапустить VPN, если что-то пошло не так |
| `vpn ssh` | настройки входа на сервер (пароль и SSH-ключи) |
| `vpn` | подсказка по всем командам |

Добавление и отключение ключей не отключает остальных — те, кто сидит в VPN,
ничего не заметят. Сервер не записывает, какие сайты кто открывает.

## Вход по SSH-ключу (по желанию)

Сейчас ты заходишь на сервер по паролю. Это нормально: сервер сам блокирует на
10 минут тех, кто 5 раз ошибся с паролем, так что подобрать его почти
невозможно. Но надёжнее входить по **SSH-ключу** — это файл на твоём
компьютере, который работает вместо пароля.

**Важно:** если выключить пароль и потерять ключ (переустановил Windows, сменил
компьютер), на сервер будет не попасть. Спасёт только консоль в личном
кабинете хостера. Если сомневаешься — оставь пароль.

Как перейти на ключ (Windows, в PowerShell на **своём компьютере**, не на сервере):

1. Создай ключ: `ssh-keygen -t ed25519` и на все вопросы просто нажимай Enter.
2. Покажи его: `type $env:USERPROFILE\.ssh\id_ed25519.pub` — выведется одна
   строка, начинается с `ssh-ed25519`. Скопируй её целиком.
   (На Mac: `ssh-keygen -t ed25519`, потом `cat ~/.ssh/id_ed25519.pub`.)
3. Зайди на сервер и добавь ключ, вставив строку в кавычки:
   `vpn ssh key add "ssh-ed25519 AAAA... твой-компьютер"`
4. **Не закрывая это окно**, открой второе PowerShell и зайди на сервер снова:
   `ssh root@IP`. Пароль спрашивать не должны.
5. Если вошёл без пароля — в любом окне на сервере: `vpn ssh password off`.
   Если не вышло — ничего не выключай, разберись с ключом.

Вернуть вход по паролю: `vpn ssh password on`. Посмотреть, что сейчас включено:
`vpn ssh`.

## Если что-то не так

**Скрипт пишет «скрипт работает только на Ubuntu 24.04»** (или `apt-get: command
not found`). На сервере стоит другая система — например, CentOS, AlmaLinux или
Rocky. В личном кабинете хостера найди «Переустановить ОС» (Reinstall), выбери
**Ubuntu 24.04**, дождись окончания и запусти команду снова. Переустановка
стирает всё на сервере и может сменить пароль root — новый хостер обычно
присылает на почту или показывает в кабинете.

**Приложение пишет «подключено», но сайты не открываются.**
Почти всегда дело в приложении: Amnezia VPN и приложения на sing-box такое
делают. Поставь Happ или v2RayTun и добавь ключ заново. Проверь, что ключ не
отключён (`vpn list` на сервере) и что `vpn check` пишет «Всё в порядке».

**Скрипт пишет «Жду, пока запись заработает» и не дожидается.**
- Опечатка в домене или в IP в A-записи.
- В Cloudflare облачко оранжевое — переключи на серое.
- Запись добавлена не в ту зону или не у того регистратора, который управляет
  доменом. Когда исправишь — просто запусти команду из шага 3 ещё раз.

**Не могу зайти на сервер: `Permission denied`.**
- Неверный пароль. Вставляй правой кнопкой, а не набирай вручную.
- После 5 неудачных попыток сервер блокирует твой адрес на 10 минут — подожди.
- Если выключал вход по паролю — заходи с того компьютера, где SSH-ключ, или
  через консоль в личном кабинете хостера.

**На мобильном интернете работает нестабильно, а на Wi-Fi нормально.**
В приложении открой настройки сервера, найди поле `mode` и поменяй `auto` на
`packet-up`. Не помогло — попробуй `stream-one`.

**Всё перестало работать разом, у всех.**
Зайди на сервер и выполни `vpn check`. Если сервер в порядке, а снаружи не
подключиться — скорее всего, заблокировали IP сервера. Выход — переехать на
новый сервер, см. ниже. Ключи при этом можно сохранить.

**Работает то через Cloudflare, то без него.**
У провайдера бывает так: то он портит связь с IP сервера, то с Cloudflare.
Поэтому в подписке два пути: через домен (если облачко в Cloudflare оранжевое —
через Cloudflare) и прямо на сервер, и Happ сам выбирает живой. Облачко после
установки можно сделать оранжевым — так пути будут действительно разными.
Повторный запуск установщика с оранжевым облачком тоже работает.

Кто добавлял старую ссылку `vless://` — у того работает как раньше, но без
переключения. Чтобы получить его, достаточно один раз добавить подписку
(`vpn link имя`), ключ остаётся тот же.

**Забыл подписку или ссылку.** `vpn link имя` на сервере. Список имён — `vpn list`.

## Советы

- **Один ключ — одно устройство или один человек.** Так видно, кто сколько
  тратит, и любого можно отключить, не трогая остальных.
- **Не раздавай VPN десяткам людей.** Когда к одному серверу ходит много разных
  людей из одной страны, его проще вычислить и заблокировать. Для себя лучше
  держать отдельный сервер, а друзьям поднять ещё один — это та же команда.
- **Повторный запуск команды из шага 3 безопасен:** ключи сохранятся. Так же
  обновляется VPN до свежей версии.

## Переезд на новый сервер с теми же ключами

Ключи привязаны к домену, а не к IP. Если старый сервер заблокировали, но он
ещё доступен по SSH:

1. Купи новый сервер.
2. Скопируй со старого на новый два файла (в PowerShell на своём компьютере,
   подставив адреса):
   ```
   ssh root@НОВЫЙ_IP mkdir -p /usr/local/etc/xray
   scp root@СТАРЫЙ_IP:/usr/local/etc/xray/config.json root@СТАРЫЙ_IP:/usr/local/etc/xray/client.env .
   scp config.json client.env root@НОВЫЙ_IP:/usr/local/etc/xray/
   ```
3. Поменяй в A-записи домена IP на новый.
4. Зайди на новый сервер и запусти команду из шага 3 с тем же доменом.

У всех, кто добавил подписку, заработает само: приложение заберёт новый IP при
следующем обновлении. У кого старая ссылка `vless://` через домен — тоже
заработает сама, а ссылку с `-ip` придётся выдать заново: `vpn link имя`. Если
старый сервер уже недоступен совсем, ставь новый с нуля и раздай ключи заново.

## Каскад: российский вход перед заграничным сервером

### Зачем это и что такое «вход» и «выход»

Обычная схема — телефон подключается прямо к заграничному серверу. Провайдер
видит, что ты постоянно гоняешь много трафика на заграничный хостинг, и рано
или поздно может заблокировать этот адрес. А на мобильном интернете бывает
режим «белых списков»: пускают только на разрешённые адреса, и заграничный
сервер не открывается совсем.

Каскад — это два сервера друг за другом:

```text
телефон, компьютер ──> ВХОД (российский сервер) ──> ВЫХОД (заграничный сервер) ──> интернет
                          └── российские сайты открываются прямо отсюда
```

- **Выход** — заграничный сервер, через который трафик уходит в интернет.
  Это обычный сервер из этой инструкции (шаги 1–5), ничего особого.
- **Вход** — российский сервер, к которому подключаются устройства. Он
  принимает трафик и пересылает его на выход.

Что это даёт:

- Провайдер дома и мобильный оператор видят только подключение к российскому
  серверу. Заграничный выход им не виден вовсе — его сложнее вычислить и
  заблокировать.
- Вход маскируется под настоящий российский сайт, поэтому есть шанс пройти и
  там, где работают белые списки (если сам адрес сервера в них попадает).
- Российские сайты (банки, госуслуги, маркетплейсы) открываются с российского
  адреса и не ругаются на «заграничный» вход.
- Если вход всё же заблокируют — российский сервер дешёвый, его легко заменить,
  а выход и его ключи останутся целы.

Домен и сертификат на входе не нужны. Вход притворяется чужим настоящим
сайтом: кто подключится к нему без ключа, увидит именно этот сайт с его
настоящим сертификатом. Свой домен на входе даже вреден — его нет в белых
списках, и он связывает вход с выходом, если у них общий домен.

### Что понадобится

1. **Готовый выход** — заграничный сервер, поставленный по шагам 1–5.
2. **Российский сервер (VPS)** с **Ubuntu 24.04 или 26.04**, чистый, без
   «готовых решений». Хватит 1 процессора и 1–2 ГБ памяти. Если хостер
   спрашивает, что поставить, — выбирай просто Ubuntu.

### Шаг 1. Возьми ссылку для входа на выходе

Зайди на **заграничный** сервер (как в шаге 2) и выполни:

```bash
vpn add cascade-ru
```

Это отдельный ключ для входа — так его трафик виден отдельно и его можно
отключить, не трогая остальные. Скрипт покажет две ссылки `vless://…`.
**Скопируй ту, что под строкой «напрямую на IP»** — в ней после `@` стоит
IP-адрес сервера, а в конце `-ip`. Её понадобится вставить на входе.

### Шаг 2. Поставь вход

Зайди на **российский** сервер и выполни ту же команду, что и для обычного
VPN:

```bash
curl -fsSL https://raw.githubusercontent.com/zleematana/vpn-setup/main/install.sh | bash
```

Если хостер дал не `root`, а другого пользователя, добавь `sudo`:
`... | sudo bash`.

Скрипт спросит:

**«Какой это сервер?»** — ответь `2` (вход каскада).

Дальше четыре вопроса:

1. **Имя выхода** — короткое имя латиницей, как ты будешь звать заграничный
   сервер, например `de`. Потом спросит **ссылку** — вставь ту, что скопировал
   в шаге 1. После этого снова спросит имя: если выходов несколько, введи
   следующий, если один — просто нажми Enter.
2. **Сайт для маскировки** — просто нажми Enter: скрипт сам проверит несколько
   российских сайтов и возьмёт самый быстрый с этого сервера. Сменить можно
   позже командой `vpn sni`.
3. **Какие ключи создать** — как и на выходе, имена устройств или людей через
   пробел. Enter — будут `phone` и `pc`.
4. **Выключить вход по паролю?** — как и на выходе: не уверен — отвечай `нет`.

Через 3–5 минут скрипт сам проверит каскад и покажет итог:

```text
✓ xray работает
✓ маскировка www.example.ru отвечает (TLS 1.3, h2)
✓ выход de (1.2.3.4:443): выход с 1.2.3.4, ~250 Мбит/с
✓ каскад целиком: вход 5.6.7.8 → выход с 1.2.3.4, ~200 Мбит/с
Всё в порядке.
```

И ниже — ссылку и QR-код для каждого ключа.

### Шаг 3. Подключи устройство

Так же, как в шаге 5 обычной установки: в Happ или v2RayTun «+» → «Вставить из
буфера» (или «Сканировать QR»). Ссылка входа начинается с `vless://` и
содержит `security=reality`. Если включены подписки (ниже), `vpn link`
покажет вместо неё адрес подписки `https://…/s/…` — добавляется так же.

Проверка: открой [ifconfig.me](https://ifconfig.me) — он покажет адрес
**выхода** (заграничного сервера, бывает в виде IPv6). Российские сайты при
этом видят адрес входа.

### Подписки (по желанию, но удобно)

Ссылка `vless://` зашивает в себя адрес входа, сайт маскировки и ключи. Сменишь
что-то из этого — всем придётся раздавать ссылки заново. Подписка — это адрес
вида `https://v.example.ru/s/…`: приложение само скачивает по нему настройки и
обновляет их раз в 6 часов. Меняешь что-то на входе — у всех подтянется само.

Что нужно: отдельный домен (подойдёт дешёвый .ru/.online/.xyz) и в его DNS
A-запись на адрес входа. Если DNS в Cloudflare — только серое облако
(DNS only), прокси Cloudflare подключение ломает. Дождись, пока запись
заработает (`dig +short v.example.ru` на входе показывает его адрес), и:

```bash
vpn sub domain v.example.ru
```

Команда получит сертификат Let's Encrypt (порт 80 открывается только на время
проверки), поставит nginx и разделит порт 443: запросы к домену подписок — в
nginx, всё остальное — в Xray. Ссылки по IP при этом продолжают работать.
Сертификат продлевается сам.

- В подписке два пути к входу: по домену и напрямую по IP, приложение берёт
  живой. Оба идут через вход — напрямую на заграницу подписка не ведёт.
- Адрес подписки не угадать (он выводится из ключа), отключил ключ — подписка
  перестала открываться.
- `vpn sub` — пересобрать подписки, `vpn sub off` — выключить (Xray вернётся
  на 443, ссылки по IP останутся).
- Домен подписок светится в открытых журналах сертификатов — не называй его
  так же, как домены выходов.

### Команды на входе

Команда та же — `vpn`, но умеет немного другое:

| Команда | Что делает |
|---|---|
| `vpn list` | ключи, через какой выход идёт каждый, кто онлайн, трафик |
| `vpn add mama` | новый ключ (идёт через выход по умолчанию) |
| `vpn add papa de` | новый ключ сразу через выход `de` |
| `vpn link mama` | снова показать ссылку и QR (с подписками — адрес подписки) |
| `vpn del mama` | отключить ключ |
| `vpn route mama de` | пустить ключ через другой выход; `auto` — через любой живой |
| `vpn exit` | список выходов |
| `vpn exit add nl 'vless://…'` | добавить выход (ссылку бери на нём: `vpn add cascade-ru`) |
| `vpn exit add de 'vless://…'` | второй путь к тому же выходу — будет запасным |
| `vpn exit del nl` | убрать выход, его ключи перейдут на выход по умолчанию |
| `vpn exit default de` | выход для ключей, у которых он не задан |
| `vpn direct` | какие сайты идут напрямую с российского адреса |
| `vpn direct add ozon.ru wb.ru` | пустить сайты напрямую, мимо заграницы |
| `vpn direct del ozon.ru` | убрать из списка |
| `vpn abroad add portal.bitrix24.ru` | пустить российский сайт через выход, с заграничного адреса |
| `vpn abroad` / `vpn abroad del …` | список таких сайтов / убрать из него |
| `vpn sni` / `vpn sni сайт.ru` | под какой сайт маскируется вход / сменить его |
| `vpn sub domain v.example.ru` | включить подписки на этом домене |
| `vpn sub` / `vpn sub off` | пересобрать подписки / выключить их |
| `vpn check` | проверить вход, каждый выход и каскад целиком (и подписки) |

Ссылку в `vpn exit add` бери в одинарные кавычки — в ней есть знаки `&` и `?`.
Любое изменение на входе перезапускает Xray: соединения рвутся на секунду,
счётчики трафика обнуляются.

**Выходы по ключам.** Каждый ключ ходит через свой выход. Удобно, например,
держать один выход только для себя, а родным выдать ключи через другой — тогда
чужой трафик никак не задевает твой сервер.

**Если выход недоступен.** Ключ ходит только через свой выход (или через
любой из своих путей к нему). Умер выход — у этого ключа перестают открываться
зарубежные сайты, но трафик не уходит ни на другой выход, ни напрямую с
российского адреса: зарубежные сайты российский адрес входа не видят никогда.
Всё, что не подошло ни под одно правило, блокируется. Переключение на любой
живой выход — только если ты сам так настроил: `vpn route имя auto`.

**Сайты напрямую.** Российские сайты и адреса и так идут напрямую с входа.
`vpn direct add` нужен для того, чего нет в общей базе: сайт увидит российский
адрес и не уйдёт за границу. Работает сразу для всех ключей, на устройствах
ничего менять не надо. Можно указать домен (`ozon.ru` — вместе с
поддоменами), IP или подсеть (`1.2.3.0/24`), набор из базы (`geosite:apple`).

**Российские сайты через выход.** Бывает наоборот: российскому сайту нужен
именно заграничный адрес. Например, корпоративный портал пускает только с
разрешённого IP, а это адрес выхода. `vpn abroad add` пускает такой сайт через
выход ключа (у каждого ключа свой выход, как и для остального трафика), это
правило сильнее и общей базы, и `vpn direct`. Домен указывается вместе с
поддоменами; если сайт при входе уводит на другой домен (например,
`auth2.bitrix24.net`), добавь и его, чтобы весь вход шёл с одного адреса.

Если нужно, чтобы сайт или приложение вообще не шли через VPN, это делается
в самом приложении на устройстве: в Happ — маршрутизация и раздельное
туннелирование по приложениям (на Android).

**Смена сайта для маскировки или адреса входа** меняет ссылки: после
`vpn sni` или переезда входа на новый сервер ссылки придётся выдать заново
(`vpn link имя`). С подписками ничего выдавать не надо: после `vpn sni`
приложения подтянут новое сами, а при переезде достаточно перенести папку
`/usr/local/etc/xray`, направить домен подписок на новый адрес и там ещё раз
выполнить `vpn sub domain …`. Ключи и
выходы при повторном запуске установки сохраняются.

### Если каскад не работает

- `vpn check` пишет **«✗ выход … не отвечает»** — с входа не достучаться до
  выхода. Проверь на выходе `vpn check` и что ключ `cascade-ru` там есть
  (`vpn list`). Если выход жив, а с российского сервера недоступен — значит,
  его адрес заблокирован для российских сетей, нужен выход с другим адресом.
- **«✗ маскировка … не отвечает»** — выбранный сайт перестал отвечать как
  нужно. Смени: `vpn sni другой-сайт.ru`.
- **На Wi‑Fi работает, на мобильном — нет** — адрес входа не попал в белые
  списки оператора. Помогает только российский сервер с другим адресом.

## Для тех, кто разбирается

Установка без вопросов — всё в параметрах:

```bash
# домен и ключи; вход по SSH не трогается
curl -fsSL https://raw.githubusercontent.com/zleematana/vpn-setup/main/install.sh | bash -s -- vpn.example.com phone laptop

# добавить SSH-ключ и выключить вход по паролю
curl -fsSL https://raw.githubusercontent.com/zleematana/vpn-setup/main/install.sh | bash -s -- vpn.example.com phone --ssh-key "ssh-ed25519 AAAA... me@pc"

# выключить пароль, ключ уже лежит в /root/.ssh/authorized_keys
curl -fsSL https://raw.githubusercontent.com/zleematana/vpn-setup/main/install.sh | bash -s -- vpn.example.com --no-password
```

Схема:

```text
клиент ── TLS (h2) ──> nginx :443, сертификат Let's Encrypt
                        ├─ /            → страница-заглушка (/var/www/files)
                        ├─ /s/<токен>   → подписка (/var/www/sub): Happ и v2RayTun — Xray JSON
                        │                 с балансировщиком, остальным — base64 со ссылками
                        └─ /<секрет>    → grpc_pass unix:/dev/shm/xray-xhttp.sock
                                            └─ Xray: VLESS + XHTTP (mode auto)
```

Что делает установщик:

- обновляет систему, ставит nginx, certbot, ufw, fail2ban (jail sshd);
- ufw: открыты только 22, 80, 443; включает BBR;
- ставит последний Xray-core с GitHub, сверяет sha256; служба `xray` от `nobody`;
- сертификат через certbot webroot, продлевает `certbot.timer`;
- страница-заглушка со случайным названием, цветом и размерами, чтобы серверы с
  этим скриптом не находились поиском по одинаковой странице; свой
  `index.html` в `/var/www/files` не перезаписывается;
- Xray: журнал посещений выключен, BitTorrent и приватные сети блокируются,
  статистика по ключам через API на `127.0.0.1:10085` (сбрасывается при
  перезапуске Xray);
- ключи добавляются и удаляются через API Xray без перезапуска;
- повторный запуск сохраняет ключи и секретный путь, рабочий сайт nginx
  заменяется только после `nginx -t`;
- SSH меняется, только если явно попросили; настройка пишется в
  `/etc/ssh/sshd_config.d/00-vpn-setup.conf`.

| Что | Где |
|---|---|
| Ключи (конфиг Xray) | `/usr/local/etc/xray/config.json`, прошлая версия — `config.json.bak` |
| Домен, секретный путь | `/usr/local/etc/xray/client.env` (там же можно задать `IP=…`, если публичный IP определяется неверно) |
| Сайт nginx | `/etc/nginx/sites-available/<домен>` |
| Страница-заглушка | `/var/www/files` |
| Подписки | `/var/www/sub/<токен>.json` и `.txt`, токен — sha256 от ключа; выбор по User-Agent в `/etc/nginx/conf.d/vpn-sub.conf` |
| Сертификат | `/etc/letsencrypt/live/<домен>/` |
| Журнал Xray | `journalctl -u xray` |

Проверено на Ubuntu 24.04. Нужен клиент на Xray-core 1.8.10 или новее.

### Вход каскада

```bash
# без вопросов: выходы, свой сайт для маскировки (необязательно) и ключи
curl -fsSL https://raw.githubusercontent.com/zleematana/vpn-setup/main/install.sh | sudo bash -s -- --entry \
    --exit de='vless://…@1.2.3.4:443?…' [--exit nl='vless://…'] [--sni www.example.ru] phone pc
```

```text
клиент ── VLESS + REALITY + XHTTP ──> вход :443 (Xray; без ключа — прозрачно на сайт из SNI)
                                        ├─ geoip:private, BitTorrent → блок
                                        ├─ vpn abroad → balancer выхода ключа
                                        ├─ vpn direct, geosite:category-ru, geoip:ru → напрямую
                                        ├─ user → balancer b.<выход> (leastPing по путям выхода)
                                        └─ остальное → b.<выход по умолчанию>
                                                         └─ VLESS + XHTTP + TLS ──> выход
```

- Состояние входа — файлы, конфиг Xray собирается из них заново при каждом
  изменении (`vpn render` — показать, `vpn apply` — собрать и перезапустить;
  если Xray не поднялся, возвращается прежний конфиг):

  | Что | Где |
  |---|---|
  | Сайт, ключ Reality, shortId, путь, выход по умолчанию | `/usr/local/etc/xray/entry.env` |
  | Ключи: имя, UUID, выход | `/usr/local/etc/xray/keys.tsv` |
  | Выходы: файл на выход, ссылка на путь | `/usr/local/etc/xray/exits/<имя>` |
  | Сайты напрямую | `/usr/local/etc/xray/direct.list` |
  | Российские сайты через выход | `/usr/local/etc/xray/abroad.list` |

- ufw: открыты только 22 и 443. Пути к выходам проверяет `burstObservatory`
  раз в минуту (`generate_204` через каждый путь).
- Сайт для маскировки подбирается по времени TLS 1.3 + h2 с самого сервера из
  короткого списка российских сайтов; крупнейшие Xray сам не советует.
- Проверено на Ubuntu 26.04, Xray 26.11.
